LUXIO STUDIO / DOCUMENTATION

Write an animation.

Use Lua to draw a frame on your strip. Luxio calls your animation repeatedly; you decide how the colors change over time.

Quick start

  1. In Studio, choose Simulator and add an animation with +.
  2. Paste this example into the editor and select Test.
  3. To use the real strip, copy your code, choose your device, add an animation with +, and paste it. Select Test to preview it, then Save to keep it on the device.
-- @preview 00d2ff,4fff7f
-- @parameter Flicker,Checkbox,true
-- @parameter Speed,Slider,50,0,100

-- A cyan glow, with live speed and flicker controls.
local count = 0

function setup()
  count = luxio_get_pixel_count()
end

function loop()
  local seconds = luxio_millis() / 1000
  local speed = luxio_get_parameter("Speed") / 50
  local level = 1
  if luxio_get_parameter("Flicker") then
    level = (math.sin(seconds * speed * 2 * math.pi / 4) + 1) / 2
  end
  local green = math.floor(210 * level)
  local blue = math.floor(255 * level)

  for i = 0, count - 1 do
    luxio_set_pixel_color(i, 0, green, blue)
  end
end

This example works on all supported strip types, including a single addressable LED/controller.

Lifecycle

setup() is optional and runs once each time the animation starts. Use it to initialize variables or draw an initial frame. loop() is required and runs roughly every 33 ms, about 30 frames per second.

Write one frame, then return. Luxio schedules the next call. Use elapsed time for motion instead of counting frames or waiting in a loop.

Variables survive between calls and reset when the animation restarts. Pixels begin black and retain their last values until you overwrite them. To move a light, redraw the background too.

Animation API

luxio_get_pixel_count()

Returns the configured number of addressable LEDs/controllers. Indices start at 0 and end at count - 1. One controller may drive a group of physical LEDs.

luxio_millis()

Returns elapsed time in milliseconds since this animation started. Divide by 1000 for seconds. It resets on every start.

luxio_set_pixel_color(index, red, green, blue, white, warm_white, cool_white)

Sets one pixel’s channels. All channel values must be integers from 0 to 255; omitted channels default to zero. Use math.floor() when calculating values. Unsupported channels must be zero.

-- RGB: cyan at pixel zero.
luxio_set_pixel_color(0, 0, 210, 255)

-- RGBW only: the dedicated white channel.
luxio_set_pixel_color(0, 0, 0, 0, 255)

-- RGBCCT only: a mix of warm and cool white.
luxio_set_pixel_color(0, 0, 0, 0, 0, 160, 95)

luxio_get_parameter(name)

Returns the current Boolean or Number value of a declared parameter. Names are case-sensitive. Read it inside loop() to pick up live changes. Reading it in setup() captures only the starting value. An unknown name raises an error.

Luxio displays the frame automatically. There is no show() or delay call. Channel intensity is separate from device brightness, which Luxio applies to the final output.

-- @parameter Speed,Slider,50,0,100
function loop()

end

Put one optional @preview in the leading Lua comments. Supply two to eight comma-separated RGB hex colors, in gradient order. Six digits are required; an optional #, mixed case and whitespace are accepted. Duplicate, malformed or misplaced previews are rejected.

This palette is a visual hint for the iOS device header, home card and saved-animation swatch. It does not set LED colors or change playback. Missing previews use a neutral background. Firmware derives the palette from source on save or play; Script.preview is included in listings and State.animationPreview describes the playing animation, including RAM previews. Requires firmware build 19.

Parameters

Declare controls in comments at the top of your animation, before any Lua code. Studio shows a checkbox for Checkbox values, a slider for Slider values, and a numeric input for Number values. Mobile clients show native controls while the animation is playing.

-- @parameter Flicker,Checkbox,true
-- @parameter Speed,Slider,50,0,100
-- @parameter Spacing,Number,8,1,64
-- Name,Type,Default,Minimum,Maximum (range for Slider and Number)
TypeControlLua value
SliderA slider between minimum and maximumNumber
NumberA numeric input with minimum and maximumNumber
CheckboxA checkbox or native on/off controltrue or false

Numbers may be decimal or negative. Minimum and maximum are separate comma-separated values; the default must be within the range. The minimum must be lower than the maximum. Values must be finite and between −1,000,000,000 and 1,000,000,000.

Use up to 16 unique, case-sensitive names, each 1–32 ASCII characters. Start with a letter; letters, digits, spaces, and underscores are allowed. Checkbox defaults are true or false. Invalid declarations show an error and cannot be played or saved.

Changes apply without restarting the animation or resetting its elapsed time. Live values stay in RAM. Save in Studio or Save parameters on mobile stores the values with the saved animation. The comments remain the defaults; the saved values override them on the next play.

Editing declarations during a test requires stopping and testing again. Slider and Checkbox declarations require firmware build 21 or newer. Number uses a numeric input; the old Boolean spelling remains supported as an alias for Checkbox. In Studio, numeric inputs apply when you press Enter or leave the field. On iOS, press Done; on Android, press Done or the Apply button.

luxio set-animation glow.lua --parameters '{"Speed":75,"Flicker":false}'
luxio set-parameters '{"Speed":25}'
luxio set-parameters '{"Speed":25}' --save

--save requires a saved animation to be running. It preserves the values without restarting playback.

RGB-only animations work on all three types. The API does not expose strip-type detection, so write white-channel animations for a specific strip and choose the matching simulator setting.

Saved colors, gradients, and animations are separate libraries. Use a native gradient for a still blend; clients offer gradients only when the device has more than one LED/controller.

More examples

Traveling color wave

Three offset sine waves spread color along the strip. Changing 4000 changes the cycle duration in milliseconds.

function loop()
  local count = luxio_get_pixel_count()
  local time = luxio_millis() / 4000

  for i = 0, count - 1 do
    local phase = (i / count - time) * 2 * math.pi
    local red = math.floor(127.5 + 127.5 * math.sin(phase))
    local green = math.floor(127.5 + 127.5 * math.sin(phase + 2 * math.pi / 3))
    local blue = math.floor(127.5 + 127.5 * math.sin(phase + 4 * math.pi / 3))
    luxio_set_pixel_color(i, red, green, blue)
  end
end

Moving dot

Moves one mint-colored pixel every 100 ms. Every other pixel is cleared on each frame.

function loop()
  local count = luxio_get_pixel_count()
  local position = math.floor(luxio_millis() / 100) % count

  for i = 0, count - 1 do
    if i == position then
      luxio_set_pixel_color(i, 46, 236, 182)
    else
      luxio_set_pixel_color(i, 0, 0, 0)
    end
  end
end

Test & save

Test runs in the simulator and on the selected device. Device previews run from RAM and do not save a library item. Starting an animation turns the strip on and keeps its current brightness. Stop ends the preview; it does not turn off the light.

Save writes to the selected device’s animation library. With Simulator selected, it saves in this browser. Saving does not start playback. Use Download .lua in the animation menu to keep a file copy.

The sidebar shows the selected device’s saved animations. Bundled examples and browser drafts belong to Simulator. To move one to a device, copy its code, select the device, create an animation, and paste the code before saving.

The simulator displays full brightness. Your device uses its own brightness and actual LED channels, so colors can look different. Test with the matching strip type and LED/controller count, then check the physical strip.

From the CLI

luxio --device 192.168.1.231 set-animation glow.lua
luxio --device 192.168.1.231 save-animation glow.lua --name Glow
luxio --device 192.168.1.231 animations

Replace the IP with your device’s address. set-animation plays from RAM; save-animation stores it for later.

Limits & troubleshooting

  • Source: up to 16 KiB (16,384 UTF-8 bytes). Saved names are limited to 63 UTF-8 bytes.
  • Memory: the device’s Lua engine has a 128 KiB allocation budget, including runtime overhead. Reuse variables and avoid growing tables every frame.
  • Execution: the device limits initialization and each frame to 100,000 Lua instructions. Initialization has a 30 ms time budget; each frame has 20 ms. Keep work short and never use while true do.
  • Libraries: base Lua functions plus math, table, string, and utf8 are available on the device. File, network, OS, module loading, debug, and coroutine APIs are unavailable. Do not rely on print, load, dofile, loadfile, or collectgarbage.
The browser simulator is useful for previewing behavior, but it does not reproduce the ESP32’s memory and timing limits. Always test on the device before saving your final animation.
